Работа от `origin/main`, `ceeb511`. `HomePage.vue` и `QuickPlayPanel.vue` сохранены без изменений; прежняя локальная перерисовка осталась в stash. Публичный сайт проверялся без входа; рабочая БД не изменялась, публикация не выполнялась.

## Проверенные причины расхождения статистики

В публичном API на момент проверки:

| Игрок | Накопленные победы / поражения | Завершённые игры в доступном архиве |
| --- | --- | --- |
| miqone | 4 / 26 | 14 |
| aanikiforov | 7 / 7 | 7 |
| krasnov | 7 / 1 | 8 |
| hempion1 | 4 / 4 | 1 |
| baracuda | 2 / 5 | 7 |

Старая таблица использовала исключительно `ModeRating`, поэтому показывала по одной новой партии и пропускала остальных игроков. Миграция `20261025190000_guest_mode_ratings` прямо задаёт независимый старт Elo с 1200; прежний `User.rating` сохранён. Причину отсутствия части записей архива по публичному API установить нельзя.

Общий список теперь сохраняет накопленные результаты пользователя, если их больше, чем сохранившихся завершённых матчей. Иначе учитывает записи матчей. Во вкладках режимов используются завершённые игры с известным режимом, включая тренировки и партии до миграции; отменённые матчи исключены. Счётчики и история Elo не переписываются. Недостающим записям не приписывается выдуманный режим.

По уточнению пользователя таблица упрощена: игрок, всего партий, победы, ничьи, поражения. В выбранном режиме добавляется Elo. Отдельных колонок «Старые партии», «без записи», «Прежний Elo» в таблице нет. Общий список упорядочен по числу партий, таблицы режимов — по текущему Elo с приоритетом игроков, имеющих рейтинговые партии.

## Остальные изменения

- Архив, PGN и повторы требуют постоянного аккаунта через HTTP и WebSocket. Профиль не раскрывает список партий гостевому/анонимному посетителю. Интерфейс предлагает вход или сохранение гостя.
- При сохранении гостевого аккаунта явно предлагается выбрать новый ник; существующий механизм сохраняет ID, игры и статистику. У выхода оставлена иконка с доступной подписью для скринридера.
- Управление игрой перенесено в правую колонку на широком экране; на узком возвращается над доской. Проверена локальная игра с ботами в браузере Velly.
- В примере мата конём освобождено f7, в примере атаки пешкой ферзь расположен на e7. Резерв уменьшается после дропа. Исправлено ошибочное утверждение о смене цвета взятой фигуры в русском тексте.
- Миграция `20261027120000_guest_last_seen`: последняя активность гостя. Суточная очистка удаляет только гостей без партий, ходов, истории рейтинга и результатов после 30 дней неактивности. Онлайн-гости и участники лобби защищены; гости с историей сохраняются.
- Команда `reset:stats` раньше удаляла все партии и сбрасывала результаты людей. Теперь удаляет только завершённые партии исключительно между ботами и сбрасывает статистику ботов. На рабочем сервере команда не запускалась.
- Профили получают собственные HTML title/description/canonical/hreflang; отсутствующие профили возвращают HTTP 404. Гости/боты — noindex. HTML профиля входит в Docker-образ сервера; обе сборки должны быть из одной ревизии.
- `.html`-алиасы и `/rules` перенаправляются; язык HTML и клиентского canonical согласован с URL. Архив — noindex, исключён из sitemap.

## Проверки

Проверки выполнялись на отдельной локальной PostgreSQL-БД `kaissa_test_20261027` и сервере `127.0.0.1:4417`, Nginx — `127.0.0.1:8417`.

- `npm test`: 195 серверных и 14 клиентских тестов.
- Docker-образы клиента и сервера собраны; ссылки на JS/CSS в HTML профилей совпадают с клиентом.
- Typecheck и сборка проекта; клиент пересобран после упрощения таблицы.
- `scripts/smoke-maintenance.mjs`: накопленные итоги без архивных записей, частичный архив, все режимы, тренировки, исключение отмен, сохранность гостей с историей, регистрационные ограничения HTTP/WebSocket, HTML профилей, безопасный сброс статистики ботов.
- `scripts/smoke-accounts-ratings.mjs`: регистрация и сохранение гостя, конкурентные запросы, отзыв сессий, атомарное сохранение результатов, откат и повтор после ошибки. Ошибка внешнего ключа в логе намеренно вызвана этим тестом.
- `scripts/smoke-live-ux.mjs`: настоящие ходы до мата, переподключение, реванш, сохранение гостя посреди игры.
- `scripts/smoke-game-regressions.mjs`: все четыре режима, очередь ходов, неверные ходы, резервы, повторы и реванш.
- `check:prerender` и `scripts/check-seo-http.mjs`: RU/EN HTML, canonical, robots, sitemap, 404 и редиректы.
- Velly `browser_open` / `browser_read`: главная из удалённой версии, таблица с накопленными итогами, форма нового ника, ограничение архива, игра с управлением справа. Положение панели дополнительно проверено встроенным скриншотом браузера.

При проверке локального сервера обнаружены два оставшихся процесса `tsx watch`, вызывавшие EADDRINUSE и временный ECONNREFUSED. Они остановлены; проверка повторена на одном сервере без watch. После упрощения таблицы исправлена ошибка TypeScript из-за избыточного сравнения внутри `v-if`.

## Дополнение: одноразовый перенос Elo и статистики в 2×2

Предыдущее ограничение (прежний Elo не перенесён) устранено подготовленным патчем `team-rating-continuity-v1`. Сохранённый общий Elo используется как исходное значение 2×2; новые рейтинговые игры пересчитываются по порядку, а не прибавляются со старыми дельтами. Накопленные итоги без записи отнесены к 2×2 по уточнению пользователя; известные результаты других режимов предварительно исключены. В профиле показываются обычные совокупные итоги режима, без отдельной пользовательской категории старых игр.

Проверены: отказ при активной игре/разрыве истории/отсутствующем участнике, сохранность оригиналов, откат транзакции при намеренной ошибке записи аудита, два конкурентных запуска, повторное применение, следующий реальный расчёт Elo с восстановленной базы и повторное сохранение результата. Новые пользователи остаются на 1200. В пользовательских API и таблице видны восстановленные результаты и Elo.

Выпуск двухэтапный по указанию пользователя. Второй коммит с удалением временного патча допустим только после подтверждения применения первого на duochess.ru. Миграции схемы, сохранённые результаты и аудит остаются в проекте и БД.
