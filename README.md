# Каисса — командные шахматы онлайн

[Играть на duochess.ru](https://duochess.ru/) · [Правила багхауса](https://duochess.ru/rules/bughouse) · [Правила 2×2](https://duochess.ru/rules/duo) · [Правила Crazyhouse](https://duochess.ru/rules/crazyhouse) · [Сообщить об ошибке](https://github.com/miqonee/kaissa/issues)

Шахматы с резервом и командные форматы на одной или двух досках. Играйте с друзьями или заполняйте свободные места ботами — собирать четырёх людей одновременно необязательно.

- **Багхаус:** две доски работают одновременно. Взятая фигура попадает в карман напарника, который играет другим цветом. Вместо обычного хода её можно выставить на свою доску.
- **2×2 на одной доске:** партнёры играют одним цветом и строго чередуются при каждом ходе своей команды.

- **Crazyhouse 1×1:** взятые фигуры меняют цвет и становятся вашим резервом на этой же доске.
- **Crazyhouse 2×2:** формат клуба на одной доске: партнёры чередуют ходы и делят резерв своего цвета. Это отдельный формат, не багхаус.

**Kaissa is an online team chess club. Play Bughouse on two boards or alternating-turn 2v2 on one board, with friends or bots. Crazyhouse is available in standard 1v1 and Kaissa’s own alternating-partner 2v2 format with shared team reserves. Russian and English interfaces are available.**

## Что есть в приложении

- Один быстрый вход **2×2 3+0** на главной; хост может сменить режим в лобби. **Багхаус и оба формата Crazyhouse** по умолчанию без часов. До старта люди заменяют ботов; отсчёт начинается после прихода человека. Можно приостановить отсчёт и дождаться друзей. Время можно выбрать вручную.
- В багхаусе без часов доска из двух ботов получает один ход за каждый ход на доске людей, с запасом максимум на два хода. Пока человек думает, соседняя доска не убегает вперёд. При одном человеке доступны пауза обеих досок и автоматическая пауза после потери соединения; после возвращения нужно нажать «Продолжить».
- Обычные и приватные лобби, код приглашения, автоматическое распределение по рейтингу, случайные и свои команды, реванш.
- Боты разных уровней: **Stockfish 18 WASM** для одной доски; **Fairy-Stockfish WASM** для багхауса и обоих форматов Crazyhouse. Боты багхауса рассчитывают карманы, защитные и атакующие дропы; при выборе близких вариантов учитывают помощь напарнику. Боты Crazyhouse рассчитывают оба резерва, включая атакующие и защитные дропы. Уровни не являются подтверждённым рейтингом Elo для вариантов с резервом.
- Подсветка легальных постановок, выбор фигуры нажатием и перетаскиванием, подсказки первой партии, компактная доска напарника на телефоне.
- Серверные часы, премувы обычных ходов, восстановление соединения, чат, тёмная и светлая темы.
- Профили, рейтинг, архив и встроенный плеер. Для багхауса плеер воспроизводит обе доски и карманы в общем порядке ходов.

**Quick Bughouse defaults to no clock, with a bot-only board paced by the human board. Solo players can pause both boards; reconnecting requires an explicit resume. Quick alternating-turn 2v2 keeps 3+0. Timed Bughouse and games with humans on both boards run independently. Play again preserves the participants, bot strength and time control.**

## Правила клуба

В багхаусе партнёры играют противоположными цветами на разных досках. Король не попадает в карман. Пешку можно выставлять только на горизонтали 2–7; двойной ход с исходной пешечной горизонтали разрешён. Шах и мат дропом разрешены. Превращённая пешка при взятии передаётся напарнику **пешкой**, даже если на доске была ферзём.

Мат проверяется с учётом фигур **уже в кармане**: возможность закрыть шах дропом спасает партию. Если легальных ходов нет, мат или пат немедленно проигрывает весь матч. Автоматического ожидания будущей фигуры нет. Сдача и флаг на любой доске также завершают матч. Правила 50 ходов, повторений и недостатка материала в багхаусе не применяются.

В Crazyhouse пат и троекратное повторение всей позиции с резервами дают ничью. В 2×2 также учитывается очередь партнёров. Правило 50 ходов и недостаток материала не применяются. Превращённые фигуры после взятия возвращаются пешками.

В режиме 2×2 без резерва действуют обычные шахматные правила, включая автоматическую ничью при пате, недостатке материала, троекратном повторении и по правилу 50 ходов.

Новые независимые рейтинги каждого режима начинаются с 1200, коэффициент Elo — 32. Матчи с гостями и матчи только против ботов сохраняются в тренировочной статистике и архиве, но не меняют публичный рейтинг. Подробные правила и переход со старого общего рейтинга описаны ниже.

Для 2×2 без резерва доступен PGN и импорт в Lichess. Crazyhouse экспортируется с `Variant "Crazyhouse"`; оба формата поддерживают встроенный плеер с резервами. Выгрузка багхауса содержит записи двух досок с `Variant "Bughouse"`; поступления фигур с другой доски не поддерживаются обычным Crazyhouse-импортом Lichess. Для полного просмотра используйте встроенный плеер.

## Запуск через Docker

Нужны Docker Engine с Compose или Docker Desktop. Из корня репозитория:

```sh
cp .env.example .env
cp docker-compose.override.yml.example docker-compose.override.yml
# Задайте собственные POSTGRES_PASSWORD и JWT_SECRET в .env.
docker compose up -d --build
docker compose ps
```

В PowerShell вместо `cp` можно использовать `Copy-Item`.

С override приложение доступно на **http://localhost:8289** — порт задаёт `KAISSA_PORT` из `.env`. Базовый `docker-compose.yml` намеренно не публикует порт клиента: он рассчитан также на внешний reverse proxy. Без override указанного локального адреса не будет.

Миграции Prisma запускаются контейнером сервера перед стартом приложения. Новая миграция добавляет nullable `Game.rulesVersion`: старые записи сохраняются, новые партии багхауса и Crazyhouse используют правила версии 2. Для новых режимов миграция схемы не нужна: `Game.mode` хранится строкой. Не редактируйте применённые миграции и не сбрасывайте рабочую базу.

## Локальная разработка

Нужны **Node.js 22**, npm и **PostgreSQL 16**. База должна быть отдельной от публичного сервиса. Например:

```sh
docker run --name kaissa-dev-db -d -p 127.0.0.1:5432:5432 -e POSTGRES_USER=kaissa -e POSTGRES_PASSWORD=kaissa-local -e POSTGRES_DB=kaissa postgres:16-alpine
npm ci
npm run build -w shared
npm run generate -w server
```

Создайте `server/.env`, который читает сервер при запуске workspace-команд:

```dotenv
DATABASE_URL=postgresql://kaissa:kaissa-local@localhost:5432/kaissa?schema=public
JWT_SECRET=replace-with-your-own-random-secret-at-least-32-characters
PORT=4000
CORS_ORIGIN=http://localhost:5173
ADMIN_USER_IDS=your_existing_user_id
```

```sh
npm run migrate:deploy -w server
npm run dev:server
# Во втором терминале:
npm run dev:client
```

Клиент: http://localhost:5173. Vite проксирует `/api` и Socket.IO на сервер. При запуске создаются системные боты и быстрые столы. Активные матчи хранятся в памяти; после перезапуска сервера незавершённые матчи помечаются брошенными, а архив остаётся в PostgreSQL.

## Проверки

```sh
npm test
npm run typecheck
npm run check:replay -w client
npm run check:seo -w client
npm run build
npm run check:prerender -w client
```

Серверные тесты используют изолированные подмены БД; тест ИИ запускает настоящий Fairy-Stockfish WASM. Полная проверка также включает локальную партию с тремя ботами, реконнект, реванш и интерфейс на телефоне. Внешние партии и публичную БД тесты не используют.

## Устройство проекта

| Каталог | Назначение |
| --- | --- |
| `client/` | Vue 3, Pinia, Vue Router, Chessground, Vite |
| `server/` | Express, Socket.IO, игровые очереди, часы, боты, Prisma |
| `shared/` | Общие типы, переносимые правила багхауса и Crazyhouse, описания режимов |
| `server/prisma/` | Схема PostgreSQL и последовательные миграции |

Багхаус рассчитывается локально на сервере: ограниченный пул из двух процессов Fairy-Stockfish по одному потоку, без внешнего AI API. При отказе движка сервер выбирает легальный ход с учётом дропов. Изменение кармана во время расчёта приводит к повторному расчёту.

## Гости, история и рейтинги по режимам

При нажатии «Играть», «Создать стол» или входе по приглашению создаётся гостевая сессия без формы. Cookie/JWT действуют 30 дней с выдачи; очистка cookie или другой браузер не позволяют восстановить гостя. «Сохранить аккаунт» меняет ник и пароль того же пользователя: ID, партии и тренировочная статистика сохраняются. Старые токены и сокеты отзываются. Вход в другой существующий аккаунт **не объединяет** истории.

В каждом из четырёх режимов независимый Elo со стартом 1200 и K=32. До 10 рейтинговых партий он помечен предварительным. Партия рейтинговая, если в обеих командах есть постоянные игроки и нет гостей; боты могут занимать остальные места. Ожидаемый результат рассчитывается против среднего рейтинга живых соперников. Матчи только против ботов и любые матчи с гостем идут в тренировочные счётчики. Сохранение гостя во время партии не меняет её статус. Незавершённые матчи не меняют рейтинг.

История показывает команды, цвет/доску, ботов и гостей **на момент старта**, причину завершения и рейтинг до/после. Архив доступен без входа, поддерживает фильтры и постраничную загрузку. Исторические общие рейтинги не переносятся в независимые рейтинги и не переписываются: такие партии помечены «Архив · прежний общий рейтинг». Старые ничьи `*` с соответствующим статусом/причиной читаются как ничьи; пат в багхаусе остаётся поражением.

### Обновление существующей установки

1. Сохраните резервную копию БД и примените `npm run migrate:deploy -w server` перед запуском новой версии. Миграция `20261025190000_guest_mode_ratings` добавляет таблицу рейтингов и поля; старые записи сохраняются.
2. Задайте собственный случайный `JWT_SECRET` длиной от 32 символов. Production больше не запускается с пустым/шаблонным секретом. Проверка TLS в контейнерах включена.
3. Вместо `ADMIN_USERNAMES` используется `ADMIN_USER_IDS` — список ID уже существующих постоянных аккаунтов. Ранее назначенный `isAdmin` сохраняется; права по никам больше не выдаются. Проверьте список прежних администраторов перед выпуском.
4. Старые JWT без версии сессии потребуют повторного входа. Перезапуск сервера по-прежнему завершает активные партии как брошенные: восстановление активных матчей после рестарта — отдельная задача.

### Дополнительные интеграционные проверки

Только на отдельной локальной БД с `test` в имени, после миграций. Для тестового сервера задайте `NODE_ENV=test` (отключает демо-витрину), `DATABASE_URL`, `JWT_SECRET`, `PORT=4417`. Затем в корне проекта с теми же `DATABASE_URL`/`JWT_SECRET`:

```sh
KAISSA_TEST_BASE_URL=http://127.0.0.1:4417 node --import tsx scripts/smoke-accounts-ratings.mjs
KAISSA_TEST_BASE_URL=http://127.0.0.1:4417 node scripts/smoke-live-ux.mjs
KAISSA_TEST_BASE_URL=http://127.0.0.1:4417 node scripts/smoke-game-regressions.mjs
```

Скрипты создают тестовые аккаунты и партии, проверяют отзыв сессий, конкурентную регистрацию гостя, атомарность/повтор завершения, рейтинги и фильтры. Второй скрипт играет до мата через Socket.IO, проверяет реконнект, реванш и сохранение гостя посреди партии. Публичный сервис и рабочую БД использовать нельзя.


После объединения обновлений проверяются все четыре режима через реальные HTTP/Socket.IO: очередность партнёров, неверные ходы, передача резерва, дропы, завершение и приглашение на реванш. Зритель не переносится в новое лобби; участник принимает приглашение сам. `npm test` включает серверные тесты и клиентские проверки сбоев сети/сессии. Временный сбой API больше не сбрасывает вход, запросы ограничены 15 секундами; создание/старт стола и отправка хода имеют ограничение ожидания подтверждения.


## Главная, демонстрации и SEO

«Быстрая игра» — отдельный блок из четырёх форматов с короткими объяснениями. Выбор меняет подпись кнопки, время и ссылку на правила; публичные столы и трансляции показаны отдельно. Нажатие создаёт цель Метрики `quick_play_clicked` с режимом. Эту цель нужно добавить в интерфейсе счётчика. Счётчик загружается только на `duochess.ru` / `www.duochess.ru`, чтобы локальные проверки не искажали продуктовые метрики.

`DEMO_ENABLED=true` включает демонстрации ботов даже при `NODE_ENV=test`; `false` отключает их. Без явного значения демонстрации выключены только в тестовом окружении. Матчи ботов видны в трансляциях по именам участников; отдельной плашки «Демонстрация» нет. В рейтинговый архив они не попадают. Перезапуск переключается между ID -1/-2.

Метаданные и статические тексты публичных страниц находятся в `client/src/content/seo-pages.json`; Crazyhouse использует существующий `crazyhouse.json`. Сборка создаёт 16 HTML-файлов: RU/EN для главной, правил, клуба, рейтинга, архива и входа. Nginx выбирает вариант по `?lang=en`, canonical и hreflang согласованы. Вход и временные маршруты игры/лобби получают `noindex, follow`; robots не запрещает их обход, чтобы поисковик мог прочитать noindex. API закрыт в robots. Гости и боты исключены из sitemap профилей. Статические страницы правил не получают фиктивный сегодняшний lastmod при каждом запросе.

```sh
npm run check:prerender -w client
# После запуска локального Nginx с новым client/nginx.conf и dist:
KAISSA_SEO_BASE_URL=http://127.0.0.1:8417 node scripts/check-seo-http.mjs
```

Проверка HTTP требует локальный backend для sitemap. Публичные URL и ранжирование поисковых систем этим тестом не проверяются. Профили и список матчей остаются динамическими: персональные превью без JavaScript потребуют отдельного серверного рендера.


Последняя правка интерфейса: быстрая игра уплотнена до переключателя режимов и кнопки с контролем времени; поясняется только выбранный режим. Нижний ознакомительный блок главной скрыт для постоянных аккаунтов. Для Crazyhouse 1×1 увеличена доска и убран пустой второй слот командной панели.

Выбор фигуры проверяется регрессионными тестами на реальном Chessground в jsdom: сдвиг доски без изменения её размера, изменение позиции между двумя кликами, touchstart, drag, премув и повторная доставка того же списка ходов. Координаты для попадания в клетку обновляются в capture-фазе до обработчика Chessground. Внешний ResizeObserver, пересоздававший DOM доски, убран: размер отслеживает сам Chessground.
